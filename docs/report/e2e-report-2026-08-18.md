# E2E 테스트 리포트 — Playwright 세팅 + 핵심 플로우 (2026-08-18)

`docs/e2e-test-prompt.md` 지시대로 Playwright를 세팅하고 핵심 플로우를 자동화. `dev` 브랜치 기준, 로컬 `npm run dev` + 실제 Supabase 프로젝트 대상으로 실행.

**환경 확인**: Supabase "Confirm email"은 **꺼져 있음** — `signUp()` 시점에 바로 세션이 생성돼 회원가입 자동화가 문제없이 동작함.

## 1. 세팅

- `@playwright/test` 설치 + `chromium` 브라우저(이미 설치되어 있었음).
- `playwright.config.ts`: `testDir: './e2e'`, `baseURL`, `webServer`(dev 서버 자동 기동, `reuseExistingServer: true`), `trace: on-first-retry`, `screenshot: only-on-failure`, `html` 리포터.
- `.gitignore`에 `/test-results/`, `/playwright-report/`, `/e2e/.auth/` 추가.
- `package.json`에 `"e2e"`, `"e2e:ui"` 스크립트 추가.

### 인증 (storageState)
- `e2e/global.setup.ts` — **작성자 A**(회원가입+로그인 후 지원 테스트용 고정 모집글 1개 생성) / **지원자 B**(회원가입+로그인)를 각각 `e2e/.auth/a.json`, `e2e/.auth/b.json`으로 저장.
- 이메일은 `teamup.e2e.<역할>.<timestamp>@gmail.com` 형식(예시로 주어진 `@example.com`은 과거 `email_address_invalid`로 거부된 전례가 있어 회피 — gmail.com은 MX 레코드가 있어 형식 검증을 통과함).
- `playwright.config.ts`의 `projects`: `setup` → `authoredA`(storageState a) → `applicantB`(storageState b, `setup`에 의존) → `chromium`(비로그인 공용 테스트).

## 3. 작성 과정에서 발견하고 고친 문제

앱 코드가 아니라 **테스트 코드 자체의 버그**였음 (참고용으로 기록):

1. **`toHaveURL(/\/recruit\/[^/]+$/)`가 `/recruit/new` 자기 자신에도 매칭됨** — 폼 제출 직후 아직 리다이렉트가 안 끝난 시점에 어서션이 즉시 통과해버려서, 실제로는 DB에 글이 잘 만들어졌는데도(직접 DB 조회로 확인) 캡처한 URL이 `/recruit/new`로 잘못 저장됨. `page.waitForURL((url) => url.pathname.startsWith("/recruit/") && url.pathname !== "/recruit/new")` 형태로 수정. `/community/new`도 동일 패턴이라 같이 고침. (`global.setup.ts`, `recruit-create.spec.ts`, `community.spec.ts`)
2. **Base UI `<Button render={<Link/>} nativeButton={false}>`는 실제 DOM이 `<a>`여도 접근성 role은 `"button"`으로 노출됨** (`useButton()`이 의도적으로 강제 부여 — 시각적으로 버튼처럼 동작하는 링크이기 때문). `getByRole("link", ...)`로 짰던 어서션(`/recruit/[id]` 없는 글 404의 "목록으로 돌아가기")을 `getByRole("button", ...)`로 수정.
3. **`TechStackUrlFilter`의 필터 칩은 `Badge`(`<span>`)라 role이 없음** — `getByRole("button", { name: "React" })`가 못 찾음. `getByText("React", { exact: true })`로 수정.
4. `recruit-apply.spec.ts`에서 모듈 최상단(import 직후)에 `fs.readFileSync`로 fixture를 읽었다가, Playwright가 **테스트 실행 전 파일 수집 단계에서 스펙 파일을 먼저 로드**하면서 아직 없는 파일이라 즉시 크래시. 함수로 감싸 테스트 실행 시점(lazy)에 읽도록 수정.

## 4. 실제 앱에서 발견한 것 (버그는 아니지만 짚어둘 것)

### P2 — "회원가입 완료" 안내 배너가 사실상 노출되지 않음
`signup()` 액션은 `/login?signup=success`로 리다이렉트해서 초록색 안내 배너를 보여주도록 만들어져 있는데, `src/proxy.ts` 미들웨어가 **"이미 로그인된 사용자의 `/login` 접근은 `/`로 리다이렉트"** 하는 규칙을 갖고 있음. Confirm email이 꺼진 지금 환경에서는 `signUp()` 시점에 이미 세션이 생기므로, `/login?signup=success`에 닿기도 전에 미들웨어가 바로 `/`로 튕겨낸다 → 사용자는 배너를 볼 새 없이 곧장 로그인된 홈 화면을 본다. 기능상 문제는 없지만(오히려 자동 로그인이라 더 매끄러움), "회원가입 완료" 문구를 보여주려던 원래 의도는 이 경로에서 죽어있는 코드나 마찬가지. 필요하면 배너 대신 "가입 완료 후 자동 로그인되었습니다" 토스트를 `/`에서 보여주는 식으로 옮기는 걸 검토해볼 만함.

### P2 — 중복 지원 방지의 에러 메시지 경로는 UI로 도달 불가
`ApplyBar`가 이미 지원한 경우 폼 자체를 숨기고 "지원 완료" 비활성 버튼만 보여주기 때문에, 서버(`applyToRecruit`)의 `@@unique([applicantId, recruitId])` 위반 catch 블록("이미 지원했거나...")은 실제 UI 흐름에서는 도달할 수 없는 방어 코드임(2탭 동시 클릭 같은 레이스 상황 제외). 나쁜 설계는 아니고(클라이언트가 먼저 막아주는 게 UX상 좋음) 오히려 의도된 이중 방어지만, "에러 메시지가 뜨는지"를 직접 검증하는 E2E는 못 만들었다는 점은 밝혀둠 — 대신 새로고침 후에도 "지원 완료" 상태가 서버에 영속되는지로 간접 검증함.

### P3 — 접근성: 필터 칩(Badge)에 상호작용 role 없음
`TechStackUrlFilter`, `RecruitForm`/`CommunityForm`의 유형·말머리 토글이 클릭 가능한 `<span>`(Badge)이라 키보드 포커스·`role="button"`·`aria-pressed` 같은 것이 없음. 마우스로는 문제없이 동작하지만 키보드/스크린리더 사용성은 떨어짐. 지금은 `data-testid`로 우회해서 테스트했음.

## 5. 테스트 데이터 격리 및 정리

- 모든 E2E 계정 이메일은 `teamup.e2e.<역할>.<timestamp>@gmail.com`, 모든 생성 콘텐츠 제목은 `[E2E]` 접두사로 식별 가능하게 격리.
- **앱 레이어(Prisma) 정리는 완료**: 이번 작업 중 쌓인 테스트 유저 18명 + 연쇄 데이터(모집 10개, 커뮤니티 글 3개, 지원·댓글 등은 `onDelete: Cascade`로 같이 삭제)를 `prisma.user.deleteMany({ where: { email: { contains: "teamup.e2e." } } })`로 정리함.
- **⚠️ Supabase Auth(`auth.users`) 쪽은 정리 못 함**: 이 프로젝트엔 서비스 롤 키(admin API)가 없어서(`SUPABASE_SERVICE_ROLE_KEY` 미설정 — `.env` 직접 수정 금지 규칙이라 추가 안 함), `teamup.e2e.*` 이메일의 Auth 계정 자체는 Supabase 쪽에 계속 남음. 테스트를 자주 돌리면 이 고아 계정이 쌓이는데, 당장 기능상 문제는 없지만(로그인 시도조차 안 하니까) 장기적으로는:
  - Supabase 대시보드 → Authentication → Users에서 `teamup.e2e.` 이메일 주기적 수동 삭제, 또는
  - CI 등에서 정기적으로 돌릴 계획이면 `SUPABASE_SERVICE_ROLE_KEY`를 테스트 전용 환경변수로 추가하고 `global.teardown.ts`에서 `supabase.auth.admin.deleteUser()`로 자동 정리하는 걸 고려.
