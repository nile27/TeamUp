description: 그날 작업을 DEVLOG.md에 자동 정리
---

TeamUp 프로젝트의 `docs/DEVLOG.md`에 오늘(또는 지정한 날짜) 작업 내역을 자동으로 정리해서 추가한다.

## 1. 대상 날짜 정하기

- 인자가 주어졌으면(`$ARGUMENTS`) 그 값을 `YYYY-MM-DD` 날짜로 사용한다.
- 인자가 없으면 시스템 날짜(오늘)를 사용한다.
- 요일은 그 날짜 기준으로 계산해서 `YYYY-MM-DD (요일)` 형식으로 만든다 (예: `2026-08-20 (목)`). 요일은 한 글자(월/화/수/목/금/토/일).

## 2. 그날 작업 수집

아래 방법으로 그 날짜에 실제로 있었던 작업 흔적을 모은다. **git log/status/find로 실제 확인된 것만** 근거로 삼고, 확인 안 된 내용은 절대 지어내지 않는다.

- `git log --since="<날짜> 00:00:00" --until="<날짜> 23:59:59" --stat`로 그날 커밋된 메시지 + 변경 파일 목록 확인.
- `git status --short`로 아직 커밋 안 된 변경사항 확인 (대상 날짜가 오늘인 경우에만 의미 있음).
- `find src prisma docs -newermt "<날짜> 00:00:00" ! -newermt "<날짜+1일> 00:00:00"` (또는 동등한 방법)로 그날 수정된 파일 중 커밋 로그에 안 잡힌 것도 훑어본다.
- 커밋 메시지, 변경된 파일 경로, 코드 diff 요약을 바탕으로 "무슨 기능을 만들었는지 / 뭘 고쳤는지" 중심으로 재구성한다. 파일명 나열이 아니라 실제 작업 내용 요약이어야 한다.

## 3. DEVLOG.md에 삽입

`docs/DEVLOG.md` 파일 구조 — **주의: 템플릿 블록 위치를 기준으로 삼지 않는다.**
- 파일 중간 어딘가에 `## 템플릿 (복사해서 위에 붙여넣기)` 코드블록 섹션이 있는데, 이건 과거에 우연히 그 자리에 놓인 것일 뿐 최신 항목 바로 위가 아닐 수 있다(예: 첫 번째 날짜 항목과 두 번째 날짜 항목 사이에 끼어있는 경우도 있음). **이 템플릿 섹션은 절대 건드리지 않되, 위치를 삽입 기준점으로 쓰지 않는다.**
- 실제 삽입 기준점은 **파일에서 정규식 `^## \d{4}-\d{2}-\d{2}`에 매칭되는 첫 번째 줄**(= 현재 가장 최신 날짜 항목의 헤딩)이다. 새 항목은 항상 이 줄 **바로 위**에 넣는다(안내문 블록 바로 다음, 첫 구분선 `---` 다음 위치).

**동작**:
1. 먼저 대상 날짜의 항목(`## YYYY-MM-DD (요일)`)이 이미 파일에 있는지 확인한다.
   - **이미 있으면**: 새로 항목을 만들지 않는다. 대신 2번에서 수집한 내용 중 기존 항목에 빠져 있는 것만 해당 섹션(한 일/막힌 것/다음에 할 것)에 보완해서 추가한다. 중복되는 내용은 다시 안 적는다.
   - **없으면**: 위에서 찾은 "현재 가장 최신 날짜 항목" 바로 위에 아래 형식으로 새 항목을 끼워 넣는다:

     ```
     ## YYYY-MM-DD (요일)

     **한 일**
     - (그날 한 일, 근거 있는 것만. 기능/작업 단위로. 커밋이 여러 개면 관련된 것끼리 묶어서)

     **막힌 것 / 알아낸 것**
     - (커밋 메시지나 코드에서 드러나는 트러블슈팅·발견 사항이 있으면. 없으면 이 섹션 자체를 생략 가능)

     **다음에 할 것 (내일의 나에게)**
     - (그날 커밋 메시지나 남은 TODO 흔적에서 유추 가능한 것만. 근거 없이 지어내지 않는다. 정 없으면 생략)

     ---
     ```

2. **그날 커밋도 없고 파일 변경 흔적도 전혀 없으면**, 최소 형태로만 추가한다:
   ```
   ## YYYY-MM-DD (요일)
   - 작업 없음

   ---
   ```

## 4. 지켜야 할 규칙

- **오직 `docs/DEVLOG.md`만 수정한다.** 다른 소스 파일, `.env`, 다른 문서는 절대 건드리지 않는다.
- **git commit이나 git push를 하지 않는다.** 파일만 수정하고 끝낸다.
- 근거(커밋 메시지, 변경 파일, diff) 없이 추측으로 작업 내용을 지어내지 않는다.
- 기존 날짜 항목의 문체·톤(반말/개조식, "~함", "~됨")을 그대로 따라간다.

## 5. 마무리

수정이 끝나면 어떤 날짜에 어떤 내용을 추가/보완했는지 간단히 요약해서 보고한다.
